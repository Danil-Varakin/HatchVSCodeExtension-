# Hatch для VS Code

Структурные патчи для исходного кода прямо в редакторе. Вместо номеров строк патч
[Hatch](https://github.com/Danil-Varakin/hatchTs) описывает, *где* менять код, в
терминах структуры самого кода, а инструмент находит это место.

> English version: [README.md](./README.md)

Расширение делает две вещи:

- **Порождает патч по вашим правкам.** База — файл, каким он последний раз сохранён на
  диске; новая версия — то, что сейчас в редакторе, включая несохранённое.
- **Переключает между патчем и кодом, к которому он относится.** `alt+O` уводит на другую
  сторону, `alt+shift+O` открывает базу и показывает, что ханк заменяет. Навигация опирается
  на дерево патчей, поэтому требует `generate.mirror`.

## Что нужно

Расширение запускает ядро Hatch отдельным процессом и несёт его с собой зависимостью.
Больше ничего не требуется: используется тот же Node, на котором работает сам редактор,
поэтому установленный в системе Node не нужен.

Грамматики tree-sitter скачиваются один раз в кеш, общий с CLI:

```bash
npm run grammars
```

## Команды

| Команда | Что делает |
|---|---|
| **Hatch: Generate Patch** | пишет `<файл>.md` рядом с файлом и открывает его сбоку |
| **Hatch: Go to the Other Side** (`alt+O`) | из ханка — в код, который он меняет, и обратно из кода — в его ханк |
| **Hatch: Go to What the Hunk Replaces** (`alt+shift+O`) | открывает базу рядом с файлом и указывает на текст, который ханк заменяет |
| **Hatch: Pick Baseline File** | сравнивать не с сохранённым файлом, а с другим |
| **Hatch: Clear Baseline Override** | снять этот выбор |
| **Hatch: Show Baseline Resolution** | показать, какая база использована и что пробовали |
| **Hatch: Show Log** | открыть канал вывода Hatch |

## Откуда берётся база

По умолчанию — сам файл, каким он сохранён на диске. Тогда патч описывает ровно те
правки, которые вы ещё не сохранили, и настраивать ничего не нужно.

**Hatch: Pick Baseline File** заменяет базу для одного файла — когда сравнивать надо с
исходной копией, лежащей где-то ещё. Выбор помнится до **Clear Baseline Override**.

Если базу использовать не удалось, в сообщении указан путь, который пробовали. Тот же
отчёт доступен в любой момент командой **Hatch: Show Baseline Resolution**.

## Куда попадают патчи

По умолчанию патч лежит рядом со своим файлом: у `src/a/b.cc` появляется `src/a/b.cc.md`.

`generate.out` переносит его. Значение **без расширения** (а также с завершающим слешем
или указывающее на существующую папку) — это директория, в неё кладётся `<имя файла>.md`;
значение с расширением — сам файл. Недостающие папки создаются, а относительное значение
считается от корня репозитория, поэтому означает одно и то же место здесь и в терминале.

`generate.mirror` держит их отдельным деревом. С конфигом

```jsonc
{ "version": 1, "generate": { "out": "patches", "mirror": true } }
```

патч для `chromium_src/browser/core/apdate.cc` пишется в
`patches/chromium_src/browser/core/apdate.cc.md`, недостающие папки создаются.

Пути отсчитываются от **корня репозитория** — ближайшей папки с `.git`. Файл вне
репозитория — ошибка, а не догадка; относительный `out` берётся от того же корня,
поэтому редактор и `hatch generate` в терминале пишут в одно и то же место. При
включённом зеркалировании `out` обязателен и всегда читается как директория.

Решение принимает ядро, а не расширение: пишется тот путь, который вернул сервис, —
ровно туда же положил бы CLI.

## Настройка

Два слоя, и они отвечают на разные вопросы.

### Политика проекта — `hatch.config.json`

Сколько контекста несёт порождённый ханк — свойство **проекта**, а не отдельного
разработчика, поэтому живёт в файле, который едет вместе с репозиторием: тогда из одной
и той же пары версий получается один и тот же патч в терминале, в редакторе и в CI.

Расширение читает его ровно так же, как CLI: поиск начинается от папки редактируемого
файла и идёт вверх, останавливаясь на корне репозитория, — конфиг выше репозитория не
применяется никогда.

```jsonc
{
  "version": 1,
  "generate": {
    "parents": { "min": 2 },
    "siblings": { "min": 1, "max": 8 },
    "bridgeGap": 2
  }
}
```

Все ключи, что на что они разменивают и значения по умолчанию описаны один раз — в ядре:
[Anchoring options и Configuration в README Hatch](https://github.com/Danil-Varakin/hatchTs#configuration).

### Настройки редактора — ваше локальное переопределение

Каждый ключ выше доступен и настройкой редактора, чтобы можно было попробовать что-то, не
трогая общий файл. Приоритет тот же, что у флага командной строки над файлом конфигурации:

```
встроенные дефолты  <  hatch.config.json  <  настройки редактора
```

| Настройка | Ключ конфига |
|---|---|
| `hatch.out` | `generate.out` |
| `hatch.mirror` | `generate.mirror` |
| `hatch.language` | `generate.language` |
| `hatch.exact` | `generate.exact` |
| `hatch.bridgeGap` | `generate.bridgeGap` |
| `hatch.parents.min` | `generate.parents.min` |
| `hatch.parents.max` | `generate.parents.max` |
| `hatch.parents.detail.base` | `generate.parents.detail.base` |
| `hatch.parents.required` | `generate.parents.required` |
| `hatch.siblings.min` | `generate.siblings.min` |
| `hatch.siblings.max` | `generate.siblings.max` |
| `hatch.siblings.detail.base` | `generate.siblings.detail.base` |

**Настройка, которую вы не трогали, в ядро не посылается вовсе** — она не может молча
перебить конфиг проекта. Заданная явно — пусть даже тем же значением, что стоит по
умолчанию, — она выигрывает для вас.

Что откуда взялось, пишется в журнал при каждом запуске:

```
config: /repo/hatch.config.json applied generate.parents.min; overridden by editor settings: generate.bridgeGap
config: none, built-in defaults only
```

Ради этой строки всё и сделано: настройка, которая молча не сработала, — худший вид
отказа.

## Разработка

```bash
npm install        # зависимость hatch должна быть доступна
npm run build      # бандл в dist/extension.cjs
npm run watch      # пересборка на изменение
npm run check      # тайпчек и тесты
```

Дальше F5 либо запуск окна разработки напрямую:

```bash
code --extensionDevelopmentPath=. /путь/к/проекту
```

Правки кода и манифеста подхватываются только после **Developer: Reload Window** в окне
с заголовком *Extension Development Host*.
